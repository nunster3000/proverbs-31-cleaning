# Admin customer directory

The owner workspace's **Customers** tab (mobile: **More → Customers**) searches saved customer records by name, email, phone, or address. Searching runs on the backend across the database, independently of the current bookings page. Results are sorted by name and ID, with 25 customers per page and an exact result count. Account/guest filters are supported. Phone-only searches of at least seven digits tolerate punctuation in saved numbers.

**View customer** opens contact details, access instructions, pet notes, and booking history (20 visits per page). **Open booking** fetches the selected booking from the backend, even when it is outside the dashboard's current bookings page. **Edit contact details** uses the existing audited owner-only update function. Sign-in email is read-only. **Add booking for this customer** selects the same customer ID and fills the manual-booking contact fields; it does not create an account or duplicate customer by default.

Directory records are created by bookings and saved profiles. This change does not add marketing contacts, public lookup, customer deletion, exports, or account invitations. No database schema or access-permission change is needed: both new read endpoints enforce the verified owner role, and database row policies remain in place. Names/contact details use text nodes, not HTML rendering. Search filter delimiters/wildcards are stripped before forming the PostgREST substring filter. Request length, page size and filter kinds are bounded.

Loading, empty results, retry controls, and pagination are included. Search selections survive dashboard refreshes, and in-progress form edits retain the existing dirty-input protection. Customer and guest sessions cannot use the directory endpoints. Production sign-in remains disabled pending sender setup.

Validation: full suite 96 tests / 95 passed / one optional native concurrency test skipped / zero failed. Owner-denial and backend search/history scoping tests passed. Isolated mobile browser checks used 57 fictional customer records: pagination, locating a record beyond page one by email, empty search, account/guest filters, saved pet notes, opening booking history/full booking, and prefilled manual booking all passed. At 390px, document width equaled viewport width. The production build passed. No fictional records were added to production.
