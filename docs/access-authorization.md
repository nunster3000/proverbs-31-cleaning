# Home-access authorization

Customer flow: deposit → walkthrough review and confirmation → access authorization badge → review business-supplied form → typed full name and both acknowledgements → signed receipt → On the way allowed. Signing does not approve pricing or collect payment.

Gabrielle manages the wording in More → Access authorization. The editor starts empty in production. Publishing requires the owner’s approval checkbox and creates a new immutable form version. A booking uses the version assigned at confirmation; an already-confirmed booking without an assigned version receives the current active version when signed. Updating the master form does not rewrite an existing signed agreement.

Migration 011 adds RLS-protected form/signature tables, owner-only publishing, customer-only signing RPCs, the customer attention count, and a database trigger preventing transition to On the way without a matching signed receipt. A signed receipt binds the form version, customer account, typed name, server time, acknowledgements, and visit snapshot. Address/date/arrival changes invalidate current authorization and require signing again; prior records are retained. Cancelled visits cannot be signed. Administrators cannot sign on a customer’s behalf. Guest/manual customers without an account need an agreed separate authorization process before their visits can use this workflow; no admin override has been added.

No production form text or signatures are seeded. Sign-in stays disabled. Gabrielle’s actual permission form and approved retention practices remain launch prerequisites. This implements recordkeeping and signing controls; it does not determine the legal sufficiency of the form.

Verification: SQL tests cover unauthorized publishing/signing, cross-customer access, required acknowledgements, stale visit/form rejection, immutable receipts, repeat submission, preserved versions, travel gating, reschedule invalidation and badge clearing. Browser testing uses a clearly marked disposable QA form in isolated local storage/database, never the production database.

Deployment order: approve/apply migrations 011 and 012 in Supabase, deploy application, add approved business form, and test with verified accounts once email authentication is available. Until migration 011 is applied the new UI shows setup pending; the backend travel restriction is not active. Do not enable launch/sign-in before completing deployment and acceptance testing.

Production setup: migrations 011 and 012 applied and verified on October 20, 2026. Both tables have RLS enabled; API roles have no direct signature write grants; anonymous signing is denied; the travel gate is installed. No production form or signature records were created. Migration 012 explicitly revokes Supabase default table grants before restoring authenticated read-only access. Business form publication and email sign-in remain pending.

## Structured agreement questionnaire (October 26 launch)

Migration 016 extends the existing private receipt with validated questionnaire answers and a server-generated booking snapshot. The business-supplied agreement is an editable draft in `assets/agreement-template.js`; it is never silently published. Blank lines for contact details, services, scheduling and signatures are replaced by the attached structured record. Unapproved payment-due and cancellation-notice terms explicitly remain “To be agreed with Gabrielle.”

Customer and private-link guest experiences use the same three-step interface: prefilled customer/visit details; entry arrangement and optional security, pet/safety, property-care and emergency-contact notes; full terms, review and explicit electronic consent. Booking address/schedule and accepted fees are server sourced, not customer-editable contract fields. A starting estimate is distinct from an accepted final amount. Submitted answers do not modify the customer profile or add paid work.

Admin More → Forms & agreements provides wording publication, representative signature authorization and signed PDF downloads/search. Gabrielle must explicitly authorize her automatic typed signature when publishing a version. The receipt records its application time and the form records the authorizing admin and time. This represents an authorized automatic signature, not a claim that she manually signed every visit. A manual countersign fallback exists for a receipt lacking a representative signature. Customers cannot countersign or publish. Existing RLS/grants keep private instructions and signatures limited to the booking customer and verified owner; a guest session remains restricted to its one booking. Neither questionnaire answers nor access codes are added to audit logs or notification emails.

Both signatures are required before On the way for structured form versions. Older versions retain their prior behavior. Signing freezes the business contacts, service, focus, included/paid extras, starting estimate, accepted fee, deposit recorded, recurrence and visit. Later catalog and quote edits never rewrite this signed record. Date/address changes retain prior receipts and require fresh signing. Publication changes do not rewrite existing receipts.

PDFs are generated locally from the server receipt using bundled pdf-lib: no public document URLs, third-party PDF service or public storage. Text signatures, Eastern timestamps, form/booking/receipt IDs and automatic-signature authorization are included. The database receipt is the source record; PDF downloads are copies for the parties. Gabrielle must review and approve the digitized wording and authorize her signature before launch. Public sign-in and guest access stay disabled until separately approved.

Production verification, October 22, 2026: migration 016 applied after explicit approval. Questionnaire/snapshot columns exist; both tables retain RLS; anonymous signing and authenticated direct signature writes are denied; the guest RPC remains service-role-only. Zero forms were published and zero signatures created by setup. Public website sign-in, Supabase email provider, signup, guest access and automatic notifications remain disabled. Gabrielle’s publication and automatic-signature authorization are still required.
